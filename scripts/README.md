# Regenerating the golden corpus

The fixtures in `__test__/golden/` are the contract. They are produced by a
real spreadsheet engine, never by this library.

## Files

| File | What it is |
|---|---|
| `cases.csv` | `case_id,date,amount` — 89 cases, 480 payments, in input order |
| `expected_libreoffice.csv` | `case_id,expected` — checked in, generated by LibreOffice Calc |
| `expected_excel.csv` | add this yourself from Microsoft Excel |
| `expected_sheets.csv` | add this yourself from Google Sheets |
| `xirr_golden_corpus.xlsx` | the workbook that computes them |

The test suites auto-detect whichever `expected_*.csv` files exist, so adding
Excel is a drop-in — no code change.

## Adding Excel

1. Open `__test__/golden/xirr_golden_corpus.xlsx` in Excel.
2. Let it recalculate (`Ctrl` + `Alt` + `F9` forces a full rebuild).
3. On the `results` sheet, copy columns A and D.
4. Paste-special as values into a new sheet, save as CSV with the header
   `case_id,expected`.
5. Replace every `#NUM!` cell with the literal text `NUM`.
6. Save as `__test__/golden/expected_excel.csv`.

## Adding Google Sheets

1. Upload the workbook to Drive and open with Google Sheets.
2. Sheets recalculates on open. Same copy/export steps as above.
3. File → Download → CSV exports only the active sheet, so put `results`
   columns A and D on their own tab first.
4. Save as `__test__/golden/expected_sheets.csv`.

## Rebuilding the corpus itself

Only needed when adding new cases. Requires `openpyxl` and LibreOffice.

```bash
python scripts/build_corpus.py                 # writes the .xlsx
soffice --headless --convert-to xlsx --outdir . xirr_golden_corpus.xlsx
python scripts/export_golden.py                # writes cases.csv + expected_libreoffice.csv
```

The corpus is seeded (`SEED = 20260803`), so it regenerates identically.
Adding cases appends; it does not renumber existing ones.

## Why the corpus looks the way it does

89 cases chosen to exercise the places implementations actually diverge:

- **conventional/** — single sign change, unique root. Should be boring.
- **horizon/** — 1 day to 50 years. Long horizons are where plain
  Newton-from-a-bad-guess diverges.
- **rate/** — near zero, exactly zero, near total loss. Relative convergence
  tests fail near zero; the -99.9% case sits below Calc's rescan floor.
- **multiroot/** — 2 to 4 sign changes. The entire reason this package exists.
- **scale/** — the same flows at 1e0 through 1e12. Catches absolute tolerances.
- **edge/** — zero amounts, duplicate dates, 60 payments.
- **nosolution/** — no root exists; the engine reports a numeric error and so
  must we, under strict policy.
- **fuzz/** — 60 seeded random flows. 17 of them have no root, which is itself
  worth pinning.
